# GCR Platform — Full Product Plan

## Context
The user has built a local discovery + booking platform (Gulf Coast Radar / GCR) starting with Beachside Circle Boats as the first client. The goal is to turn this into a multi-tenant SaaS where local businesses get their own dashboard, connect their tools (POS, socials, booking), and GCR earns a % of every booking it drives — while maintaining real-time data sync across all channels.

---

## What's Already Built
- **cybercheck-api-database** — Node/Express API, Supabase DB, full booking system, analytics tables, SMS (Twilio), email (Resend)
- **cybercheck-login** — Admin dashboard (admin.html) + business owner dashboard (index.html)
- **circle-boats-main-** — Circle Boats live site (Vercel), full booking modal, Stripe/Square checkout
- **launching-GCR** — GCR frontend with entity listing pages, profile pages, category pages
- **Bookings table** already has: site_id, payment_provider, customer data, fleet_type_id, time_slot_id
- **Analytics tables** already have: page_views (UTM), conversions (UTM + booking_id), attribution_data

## Phase 1 — Business Onboarding via Admin Email Invite
*Foundation everything else builds on*

### What it does
Admin selects any business in admin.html → clicks "Invite Owner" → fills in owner email + business data → system sends branded email → owner clicks link → sets their password → lands on their own dashboard (like index.html) showing only THEIR business data.

### How to build
**Backend — routes/admin.js**
- `POST /api/admin/invite-business` — creates business record + user record with role='owner', generates signed invite token (JWT, 48hr TTL), sends email via utils/email.js
- Add `invite_token` + `invite_expires` columns to users table (migration)
- `POST /api/auth/accept-invite` — validates token, sets password_hash, marks user active, returns login JWT

**Email template — utils/email.js**
- `inviteOwnerHtml(data)` — branded invite email with one-click link: `https://[dashboard-url]/accept-invite.html?token=XXX`

**Frontend — cybercheck-login/admin.html**
- "Invite Owner" button in business list row
- Modal: owner email, owner name, pre-filled business name
- Calls `POST /api/admin/invite-business`

**New page — cybercheck-login/accept-invite.html**
- Reads `?token=` from URL
- Shows "Set your password" form
- Calls `POST /api/auth/accept-invite`
- On success → redirects to `index.html` (owner dashboard)

**Owner dashboard — cybercheck-login/index.html**
- Already exists — just needs to show only that owner's site_id data
- Gated by role='owner' JWT (already handled by auth middleware)

## Phase 2 — GCR Real-Time Sync + Book Now Button
*Make GCR a live storefront, not a static directory*

### What it does
- Circle Boats (and any future business) shows on GCR "Things to Do" with live data
- When owner updates their dashboard (hours, photos, description, pricing), GCR page updates in real time — no manual re-import
- "Book Now" button on GCR listing card AND profile page opens booking modal inline (same flow as circle-boats-main- links.html)

### How to build

**Data sync — already solved**
- GCR frontend calls `/api/gcr/entity/:slug` which reads from gcr_entities table
- Owner dashboard calls `/api/dashboard/*` which writes to businesses + site_content tables
- **Gap:** gcr_entities is a separate table — need a sync trigger/webhook so when site_content updates, the matching gcr_entity also updates key fields (name, description, hours, images, booking_url)
- Add `POST /api/admin/gcr/sync-entity/:site_id` — reads businesses+site_content, writes to gcr_entities

**Book Now button — launching-GCR**

## Phase 3 — Booking Source Tracking + Channel Pricing
*Know where every dollar comes from*

### What it does
Every booking knows its source: GCR listing, links.html, Facebook ad, Google, direct website. Owners see a "Booking Sources" chart in their dashboard. They can set a different price (or discount) per source channel — e.g., "$10 off if you book via GCR."

### How to build

**UTM capture at booking time**
- booking flow in circle-boats-main-/index.html + links.html: read `utm_source` from URL params, store in sessionStorage
- On booking POST, include `utm_source`, `utm_medium`, `utm_campaign`, `referrer` in request body
- Add `booking_source` column to bookings table (migration): stores 'gcr', 'facebook', 'google', 'direct', 'links', etc.
- Backend saves it: `booking.booking_source = req.body.utm_source || 'direct'`
- **Already have:** conversions table with booking_id + utm_source — just need to surface it in the dashboard

**Source-specific pricing**
- Add `channel_pricing` JSONB to site_content: `{ "gcr": { "discount_pct": 10 }, "facebook": { "discount_pct": 5 } }`
- Booking modal reads channel from utm_source, applies discount at price calculation step
- Owner sets this in dashboard: "Manage Channel Pricing" section

**Dashboard — Booking Sources widget**
- Add "Sources" tab to bookings page in admin.html and index.html
- Bar chart: GCR / Facebook / Google / Direct / Links — bookings count + revenue per source
- Calls `GET /api/dashboard/bookings/by-source` — groups bookings by booking_source

## Phase 4 — Multi-Business Referral + Verified Review Platform
*Network effect + trust layer*

### What it does
- GCR earns a referral % on every booking it drives (tracked via utm_source=gcr)
- After a completed booking, customer gets an SMS with a one-time verified link to leave a review — not Google, YOUR platform — verified from actual payment
- Customers can also record a video review, share to social (FB/IG/TikTok), and earn a % of future bookings their link drives (influencer pages)
- Influencer links are tracked like utm_source=influencer_[userId] — Stripe/Square payment splitting handles their cut automatically

### How to build
- `booking_token` column already exists in bookings table — use this as the one-time review link key
- `POST /api/public/review/:booking_token` — validates token is unused, creates review record, marks token used
- Video reviews: upload to Supabase Storage, attach to review record, generate shareable URL
- Influencer page: user registers, gets unique slug, all bookings from their slug tracked + paid out via Stripe Connect
- GCR referral %: configurable per-entity in gcr_entities: `referral_pct` (default 5%)

## Phase 5 — POS + Third-Party Booking Integration
*Real-time availability from FareHarbor, Rezdy, Square, Toast*

### What it does
- Business connects their existing booking platform (FareHarbor, Rezdy, Square Appointments, Toast)
- GCR shows REAL availability — not just "Book Now" but "3 spots left at 2pm"
- For businesses that don't have a booking system, they use the built-in one
- Referral % applies to any booking made through GCR regardless of which platform processes it (webhook confirms)

### How to build
- OAuth flows per platform: FareHarbor, Rezdy, Square Appointments — store tokens in site_content.integrations JSONB
- Availability proxy endpoint: `GET /api/public/availability/:site_id?date=` — checks connected platform first, falls back to internal
- Webhook receivers for each platform confirming booking completed → trigger GCR referral calculation
- POS (Square/Shopify) inventory sync: product catalog → searchable local inventory on GCR

## Phase 6 — Local Loyalty Program + Day-of SMS Offers
*Convert tourists into repeat customers*

### What it does
- Tourists sign up for "Gulf Coast Insider" on GCR — they get an SMS with same-day deals from businesses with open slots
- Businesses opt-in to broadcast day-of availability to loyalty members
- After any booking, customer gets SMS next morning: "Did you enjoy [business]? Here's what's available today nearby…"
- Creates a local co-op SMS network — all businesses benefit from each other's customers

### How to build
- `loyalty_members` table: phone, email, interests, location, signup_source
- Opt-in at booking confirmation: "Join Gulf Coast Insider for same-day deals?" checkbox
- Daily cron job: queries businesses with open slots for today → sends SMS blast to nearby loyalty members
- Already have Twilio SMS infrastructure (utils/sms.js) — just need the cron + member table

Linktree / Stan Store — the "links page" concept but no booking, no verified reviews, no revenue share
Airbnb Experiences — closest to the activity booking piece but they own the customer, take 20%, no white-label, not local-first

	•	One-time token review links tied to confirmed payments
	•	Influencer affiliate links generated from actual customer video reviews
	•	Local SMS co-op across multiple businesses sharing tourist traffic
